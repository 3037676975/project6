PROJECT6 · SOURCE OF TRUTH

AI Web Video Studio

Project6 不是在线剪辑 SaaS，也不是服务器视频渲染平台。它是一个轻量的「AI HTML 视频资源中心 + Garden 视频制作规范库 + 播放/本地导出工作台」。制作主要由 AI 完成，Project6 负责整理、保存模板和源码、预览、播放、本地导出。

一、重新定义 Project6

制作主要由 AI 完成，Project6 负责整理、保存模板和源码、预览、播放、本地导出，不负责重型视频生成。

核心目标是让学生和低预算用户能够利用 ChatGPT + Garden Skills + 免费/低成本 TTS + Web 动画，在不购买 GPU、不购买昂贵视频生成 API、不依赖大型剪辑软件的情况下制作漂亮的知识类视频。

用户给出主题 / 文章 / 文案 ↓ ChatGPT / AI 制作层 ↓ 严格执行 Garden Skills / web-video-presentation ↓ Script → Theme → Outline → Chapter → Step ↓ HTML / React / SVG 动画 + 配音 ↓ Project6 加载与播放 ↓ 【播放并导出】 ↓ 浏览器本地录制 ↓ 下载到用户电脑

服务器保存什么？

内容服务器保存
HTML / React / CSS / JS✅
脚本 / Narration / Outline✅

用户导出视频 / 大量缓存❌

二、Garden Skills 必须成为制作标准

用户口中的“Garden Scale”在项目中统一对应 Garden Skills 的 web-video-presentation 视频制作能力。它不是“参考风格”，而是 Project6 的核心制作规范。

原始内容 ↓ Narration Script ↓ Theme ↓ Outline ↓ Implementation Mode ↓ Chapter ↓ Step ↓ Audio ↓ Auto Play

视频舞台统一按照 16:9 设计，优先使用 1920 × 1080 的视觉坐标和布局逻辑。关键约束是：

Chapter → Step → 一段 Narration。不能再用“这个画面 5 秒、那个画面 7 秒”的粗糙固定时长逻辑代替真正的音画同步。

三、AI 每次制作视频必须按这个流程

① 理解主题 ↓ ② 写完整 Narration ↓ ③ 拆 Chapter ↓ ④ 拆 Step ↓ ⑤ 为每个 Step 设计画面 ↓ ⑥ 选择 Garden Theme ↓ ⑦ 制作 HTML / React / SVG 动画 ↓ ⑧ 生成对应配音 ↓ ⑨ 检查 Narration / Step 数量与顺序 ↓ ⑩ Project6 加载、预览、播放

Narration 数据应该成为声音和 Step 数量的重要事实来源，防止画面、声音、章节结构互相漂移。

四、Project5 只负责 TTS

Project5 是独立 TTS HTTP 服务。Project6 不复制 Edge / Kokoro 模型代码，不把 TTS 推理塞进当前项目。

Project6 ↓ 请求 TTS Project5 独立服务 ↓ Edge TTS ↓ zh-TW-YunJheNeural
engine = edgevoice = zh-TW-YunJheNeuralspeed = 1.10显示名：ETG1 / Edge 云哲 · 台湾男声

音频也尽量不长期落 Project6

Project6 → Project5 → 音频 Response → 浏览器 Blob → 播放 / 临时缓存

必要时使用浏览器内存或 IndexedDB 临时保存。目标是：最终视频不落服务器，生成配音默认也不长期落 Project6 服务器。

五、浏览器播放时直接本地导出

HTML 不是“神奇地直接变成 MP4”，正确思路是让浏览器本地捕获视频舞台，同时播放 HTML 动画、TTS 与音效，并用浏览器录制能力生成 Blob。

点击【播放并导出】 ↓ 浏览器捕获当前舞台 / 标签页 ↓ HTML 动画 + TTS + 音效同步播放 ↓ MediaRecorder / 浏览器录制 ↓ Blob ↓ 自动下载到本地
Project6 服务器不接收最终视频、不长期保存视频、不负责视频编码。第一版优先 WebM，后续再评估 WebCodecs / ffmpeg.wasm 在浏览器本地转换 MP4。

浏览器授权

如果继续采用 DOM / React / CSS / SVG，浏览器通常要求用户主动授权捕获当前标签页。这是正常的安全限制，不应该为了去掉一个授权弹窗就重新造一个重型 Canvas 视频引擎。

六、Garden 模板、主题和中文手册

模板中心不能只是“换几个颜色”。Theme 至少要描述颜色、字体、舞台间距、圆角、分割线、Hero 数字、阴影、装饰和 Mood。

后台的 Garden 中文手册应逐步覆盖：

Garden 入门ScriptThemeOutlineChapterStepNarrationAudioAuto Mode本地导出常见错误AI 制作规范

这套中文手册既给人读，也给 AI 读。未来 AI 每次开发或制作前都应读取相应规范。

七、动画与音效资源库

动画资源

Project6 要逐步积累文字动画、数字动画、图表动画、卡片动画、流程图、SVG、Logo、背景、进退场、强调和加载动画。优先研究 Lottie Web、Anime.js、Motion 等开源能力，并给可复用资源稳定 ID。

number-counter-01 title-reveal-03 svg-flow-arrow-02 card-stack-04

音效能力

Howler.js 负责音效播放控制；Tone.js 可用于浏览器程序化生成 Tick、Beat、Synth、Transition 等简单声音。免费素材优先整理许可证清晰的资源，例如 Kenney Assets。

UI: click / switch / hover / confirm / error Transition: whoosh / swoosh / sweep / rise Technology: digital / beep / data / scanner

Scene 只需要引用类似 sfx: ui-click-04 的稳定资源 ID。

八、后台应该轻，职责要清楚

新后台围绕：工作台、视频作品、模板中心、Garden 中文手册、动画资源、音效资源、配音测试、素材库、制作规范 / 项目总纲。

第一阶段不要把这些做成核心： 渲染队列、GPU 状态、视频服务器、服务端转码平台、大型任务 Worker、复杂时间线剪辑器。

九、统一视频项目数据结构

presentations/ └── rag-intro/ ├── manifest.json ├── README.md ├── script.md ├── outline.md ├── src/ │ ├── chapters/ │ │ ├── 01-intro/ │ │ │ ├── index.tsx │ │ │ └── narrations.ts │ │ ├── 02-rag/ │ │ └── 03-summary/ │ └── styles/ ├── assets/ │ ├── images/ │ ├── svg/ │ └── lottie/ └── sfx.json

manifest.json 至少描述标题、简介、Theme、章节数量、Step 数量、封面、作者、音效、默认 Voice 和状态。Project6 尽量自动读取 manifest，而不是把作品信息硬编码到页面。

十、第一阶段不要贪多

先把一条链路做真，再把资源库做大。
60～90 秒文案 ↓ 严格 Garden Skills ↓ 一个 Garden Theme ↓ 5～10 个 Step ↓ HTML 动画 ↓ Project5 / Edge 云哲台湾男声 ↓ 自动播放 ↓ 音画同步 ↓ 浏览器本地录制 ↓ 下载 WebM

第二个实验再换 Theme；第三个实验再加入 Whoosh、Click、Tick、Lottie、SVG。之后才扩充主题、模板、音效和动画资源库。

最终产品目标： 利用 ChatGPT + Garden Skills + 免费 TTS + Web 动画，让学生不用 GPU、不买视频生成 API、不购买昂贵剪辑软件，也能制作漂亮的知识类视频；Project6 只负责管理和播放，最终视频直接在用户浏览器生成并保存到本地。

十一、强制开发门禁

从现在开始，每一次 Project6 开发都必须先读本总纲和 PRD，再定位当前 Phase。开发完成必须自检；没有 PASS，不进入下一阶段。

Gate 0读总纲 + PRD
Gate 1定位当前阶段
Gate 2目标对齐检查
Gate 3只做当前任务
Gate 4/5自检 → PASS

每次开发前必须明确

【当前定位】 Phase： 已完成： 本次目标： 明确不做： 【对照总纲】 产品方向：PASS / FAIL Garden 逻辑：PASS / FAIL 轻量服务器原则：PASS / FAIL TTS 边界：PASS / FAIL 可验收性：PASS / FAIL

开发后必须检查

  • 实际修改了哪些文件、页面、数据和功能？
  • 用户如何一眼判断它真的完成？
  • 有没有假按钮、假状态、只有 UI 没逻辑？
  • 有没有音画不同步或 Step / Narration 数量不一致？
  • 有没有把最终视频错误地上传到服务器？
  • 有没有重复建设 Project5 TTS？
  • 文档和实际代码是否一致？
PASS → 记录完成 → 允许进入下一步。FAIL → 列出失败项 → 继续完善 → 重新自检。没有 PASS，不进入下一阶段。
