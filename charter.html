不是把很多视频塞进一个页面，而是让每一个视频成为自己的项目。

Project6 的核心从“做一支视频”升级为“长期管理很多支视频”。每个项目拥有自己的脚本、Scene、视觉、配音、验收、录制和历史；项目之间只共享制作能力，不共享业务状态。

独立项目详情

每个视频有自己的详情页和 `presentations/<project-slug>/` 目录，脚本、TTS、Gate、播放器和录制逻辑完全隔离。

共享能力，不共享状态Garden、组件、GSAP、TTS Runtime 可以复用；项目脚本、音频、确认状态不能复用。
旧项目默认不可被新项目改坏创建新视频必须创建新 slug、新目录、新详情页和新的本地状态 key。
项目列表是唯一总入口用户先选择视频，再进入制作。禁止把某一个视频的详情重新塞回 works.html。

03Garden 画面 + MotionVisual

永远不能破坏的四条原则

Project-first

所有生产动作必须知道自己属于哪个视频项目。

Isolation

每个项目的数据、音频、Gate 和本地状态必须隔离。

Reproducible

旧视频随时能重新打开、预览、录制，不依赖最新项目。

Gate-driven

先验收当前阶段，再进入下一阶段，不用新功能掩盖未完成状态。

开发顺序固定：读总纲 → 读 PRD → 读 Active Decisions → 读 Development Status → 定位当前项目 → 读取该项目 ACCEPTANCE → 实现 → QA → 更新状态。新增视频时，第一件事不是改 Harness Engineering，而是创建一个新的独立 Project。
