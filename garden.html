Garden · Web video presentation

先有口播节拍，再有画面。

Garden 在 Project6 里不是一种固定“风格”，而是一套生产秩序：先确定 Narration，再拆 Chapter / Scene，再决定 Theme 与画面。动画只服务当前 Scene，不抢叙事控制权。

01 · Script / Narration

视频不是先做 HTML 再想配音，而是先写完整口播。口播是画面数量、节奏和最终 TTS JSON 的事实来源。

主题 / 文章 ↓ 完整 Narration ↓ 拆 Chapter ↓ 拆 Scene

02 · Chapter

Chapter 只用于整片内部组织，不再形成独立 TTS 交接流程。用户最终面对的是一个完整 Project、一份完整脚本和一个整片预览。

03 · Scene

Scene 是视频里的最小叙事单位。当前 Harness Engineering 使用连续 001～042 编号。

固定规则：一个 Scene 对应一段 Narration，对应一个稳定音频编号，例如 001.mp3 ↔ Scene 001。

04 · Theme

Theme 统一颜色、字体、空间密度与视觉气质。组件库只能提供结构和微交互原型，不能把社区组件原始配色整块复制到成片。

后台 UI 与视频 Theme 是两套系统：后台负责高效生产，成片视觉负责叙事表达。

05 · Emil + GSAP

Emil Skills 负责判断“该不该动、为什么动、多久”；GSAP 负责 Timeline、SVG、MotionPath、Flip、Morph 等真实执行。

Garden Scene ↓ Galaxy 找视觉原型 ↓ Theme 适配 ↓ Emil 判断动画机会 ↓ GSAP 执行 ↓ Screenshot / Motion QA
禁止：用整屏 fade / pop 当万能答案；文字正在阅读时持续漂移；动画自己切换下一 Scene；为了“更炫”添加与讲解无关的运动。

06 · Audio

当前正式人物配音路线是本地 IndexTTS 2.5。Project6 负责完整 JSON、稳定编号、配音源导入与整片验证。

Project6 full-tts-tasks.json ↓ 本地 IndexTTS 2.5 ↓ 001.mp3 / 002.mp3 / ... ↓ ZIP ↓ IndexedDB 配音源 ↓ 001 ↔ Scene 001 ↓ 整片音画预览

v63 不再提供独立动画音效库。SFX / BGM 仍保留，但只有 Gate D 整片音画 PASS 后，才在具体 Project 内处理。

07 · 验收 Gate

A 完整口播 B Garden 视觉 + Screenshot QA C 本地 IndexTTS / 配音源 D 整片音画 E 项目内 SFX / BGM F 高清本地录制

Gate 是依赖关系，不是进度装饰。上一阶段没有满足验收条件，下一阶段不能靠“先做着”绕过去。

08 · 常见错误

  • 先做漂亮页面，再硬塞一段长配音。
  • 所有 Scene 使用相同左右结构，只替换文字。
  • 用人工固定秒数猜中文语义节点。
  • 把人物配音和 SFX 混成一个资源池。
  • 为了资源完整而先堆脱离真实项目的素材库。
  • 页面升级了，Charter / PRD / Development Status 仍写旧版本。
