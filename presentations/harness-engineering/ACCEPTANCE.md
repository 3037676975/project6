# Harness Engineering · 整片验收标准 v60

> 当前正式产品构建：**Project6 v60**。正式播放器 `full-video.html?v=60`，录制控制台 `record.html?v=60`，纯成片窗口 `capture.html?v=60`，视频作品页 `works.html?v=60`。

## 当前验收对象

- 完整视频：42 Scene
- TTS：整片一次 JSON / 一个或多个完整 ZIP 配音源
- Recording：双窗口控制台 + 纯成片捕获窗口 + 1080P/1440P/4K 输出

## Gate B · 视觉一致性 v60
状态：**REVIEW**

- [x] `capture.html` 与正式播放器使用同一套 Garden 视觉依赖链。
- [x] 录制控制台深色 CSS 不与成片 DOM 共页，不得污染 Scene 标题颜色、字体继承和布局。
- [ ] 用户实机抽查 Scene 001～004 与后续 Scene：正式播放器与 capture.html 主标题颜色、字号、位置一致。

## Gate C · 本地 TTS 配音源库 v60
状态：**REVIEW**

- [x] 上传 ZIP 时自动解压并保存到当前浏览器 IndexedDB。
- [x] **单个 MP3 / WAV / M4A / OGG 不持久保存**，只能作为当次临时导入。
- [x] 一个 ZIP 形成一个独立配音源：`配音源 1 / 配音源 2 / 配音源 3 ...`。
- [x] 每个配音源独立保存原 ZIP、文件名、创建时间、001～042 音频 Blob 和完整度。
- [x] 支持 ZIP 子目录与 001～042 自动匹配。
- [x] 配音源库支持：设为当前、试听 001～004、删除。
- [x] 当前配音源选择刷新后保持。
- [x] 录制控制台可直接选择已保存配音源，无需重复上传。
- [x] 正式播放器 / capture.html 按当前 Scene 自动加载当前配音源的对应音频。
- [x] 配音源不上传服务器、不提交 GitHub；数据范围仅当前浏览器/当前设备。
- [ ] 用户实机确认：上传 ZIP → 刷新 → 配音源仍存在。
- [ ] 用户实机确认：上传第二个 ZIP 后可在配音源 1 / 2 间切换并试听。
- [ ] 用户实机确认：单独上传音频后刷新，不出现在配音源库。
- [ ] 用户实机确认：录制控制台选择配音源后，纯成片窗口使用对应 001～042 旁白。

## Gate F · 高清本地录制 v60
状态：**REVIEW**

- [x] 成片窗口与控制窗口分离；控制台、REC 按钮、配乐按钮不进入最终视频。
- [x] 控制台通过 `BroadcastChannel('project6-harness-v60')` 控制成片窗口。
- [x] 本地配乐与当前配音源都在成片窗口播放，并可通过标签页音频进入录制。
- [x] 输出画质可选：1080P 24 Mbps、1440P 40 Mbps、4K 65 Mbps；目标 60fps。
- [x] 显示真实 SOURCE → OUTPUT；源分辨率低于输出时明确提示存在放大。
- [x] 录制四态：开始、暂停/继续、停止并保存、取消并丢弃。
- [ ] 用户实机确认：当前配音源旁白、配乐与画面均正确进入最终文件。
- [ ] 用户实机确认：录制文件无工作台、无控制栏、无 REC 浮层且可播放。

## 版本一致性 Gate

以下任意一项出现即 FAIL：
1. 当前版本不是 v60；
2. `assets/version.js`、`full-video.html`、`record.html`、`capture.html` 缓存参数不一致；
3. 配音源库 ZIP/单片保存规则被破坏；
4. 页面升级而 DEVELOPMENT_STATUS / ACCEPTANCE 未同步。

## 当前结论

v60 在 v59 双窗口录制基础上新增浏览器本地持久化配音源库。完整 ZIP 被视为可复用的“配音源版本”，单个音频保持临时属性；后续浏览、预览和录制可以直接切换已保存的配音源。
